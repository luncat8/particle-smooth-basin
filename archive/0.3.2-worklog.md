# 0.3.2 saved-state, versioned logs, first real capture worklog

## review of 0.3.1 (first real-device run)

The capture `experiments/logs/0.3.1-tests-2026-10-25-23-47-16.log` (Windows, Chrome 151, DPR 1.25, NVIDIA, 20 threads, WebGPU present) answered the question the plan had been waiting on and exposed three harness defects.

- **Numbers.** All 11 matrix cases pass: worst frame p95 is 2.22 ms at `stirred-cap` (1500 beads, held drag + splash), the 810-bead default scene is 1.21–1.28 ms, and every case's rAF interval stays pinned at 5.6 ms, i.e. the display refresh, so the frame work is far below vsync at every scene weight. The Canvas2D render stage is 0.57–1.08 ms and the CPU simulation 0.30–1.15 ms p95: both stages matter, neither dominates, and a WebGPU port has nothing to win. The first gate condition in `0.3-plan.md` fails, so the gate stays closed — recorded in the plan.
- **Defect 1 — the timer line was wrong.** `timer 0.00 us`: the resolution was measured in microseconds and then divided by 1000 and printed with two decimals, so 5 µs became `0.01` and 1 µs became `0.00`. It now prints in the unit it measures, one decimal.
- **Defect 2 — CRLF.** The run log was written in Python text mode, so the whole file came out `\r\n` on Windows, against the repo's LF convention. Log files are opened with `newline="\n"` now.
- **Defect 3 — no save feedback, duplicate appends.** Pressing `Save log` again re-posted the same section and silently pasted the same numbers into the file a second time; the button gave no sign that the first save had happened.
- **Noise.** `experiments/harness.js` let the fake page print its whole internal log into the run log, including a line about `browser-fake.log` that looked like a real save.

## implementation

- **Saved state, on both sides.** The page keeps the exact text it last saved. While the log still matches, `Save log` reads `Saved ✓`, is highlighted, and is disabled, with the target path in its tooltip; the status line carries `PASS · … · saved <path>`. Any new log line re-enables the button, so a second run can be saved and the first one cannot be saved twice. Pressing it in the narrow race before the state updates returns early with `already saved · <path>` instead of posting. The runner enforces the same rule independently: it compares the posted body with the previous section and answers `{"saved": false, "duplicate": true}` without touching the file, which is what protects two tabs or a stale page. The "already saved" feedback deliberately adds no log line — that would change the text and re-arm the button.
- **Copy feedback.** `Copy log` flashes `Copied ✓` for 1.4 s and reports through the status line, which now has a green tone for success next to the red one for failure.
- **Versioned log names.** `VERSION` at the repo root (now `0.3.2`) is read by `run_tests.py`, which names runs `<version>-tests-<date-time>.log` and passes `?version=` to the page so a `file://` download carries the same prefix. The version is also in the header line and in the page's own run line (`browser tests 0.3.2 · …`).
- **Quieter node lint.** `experiments/fake-dom.js` accepts a console stand-in, so `experiments/harness.js` captures the sandbox page's output instead of printing it and reports only its own summary. `run("quick", …)` accepts overrides so the lint runs its matrix with a handful of frames, and `checks: false` reuses the previous check verdict for the second scenario.
- **New lint assertions for the save path:** one post per run, `Saved ✓` + `saved` class + disabled afterwards, a second `save()` posting nothing, a new run posting again, and a `duplicate` response reported as `already in … nothing appended` while the log stays saved.
- **Measured node penalty, documented.** V8 does not optimize code compiled through `vm.runInContext`: a tight typed-array loop took 15 ms in the main realm and 2.2 s in a context on the same node; the engine booted in the fake DOM runs ~10× slower than `require`d. That is why the sandbox checks are wiring checks only, and why the lint's second scenario reuses checks instead of re-running them. Written into `findings-pitfalls-skills.md`.

## validation

- `node experiments/harness.js` — pass: 13 ids, 7 checks, quick matrix, `Saved ✓` state, second Save silent, duplicate response accepted as saved, 6 s for the sandbox page path.
- `node experiments/smoke.js`, `experiments/thermal.js`, `experiments/bench.js` — pass, unchanged (bench 810 beads 0.38–0.56 ms/frame, near-cap 1500 beads 0.91–1.24 ms/frame, equilibrium 0.500/1.000, no NaN).
- `python3 run_tests.py --node-only` — pass; log written as `experiments/logs/0.3.2-tests-2026-10-26-00-00-56.log`.
- Server path exercised by hand: two identical `POST /__log` bodies produced one `--- browser tests (tests.html) ---` section, the second answered `duplicate: true`; the resulting file has zero `\r` bytes and the UTF-8 `·` survived; `/` still redirects to `tests.html` and the page URL carries `?version=0.3.2`.
- Still not validated in this sandbox: canvas pixels, real frame times, and the visual saved state in a real browser. The saved-state logic and the duplicate handling are covered in the fake DOM; the appearance is not.

## next step
