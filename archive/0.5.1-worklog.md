# 0.5.1 couplings × scenes worklog

## Review of 0.5.0

The two-way field is already bounded and the prior node checks cover feed 0 and the five scene presets. The browser perf matrix still only measured one high-link coupling; it could not show whether the six live couplings behave differently on the other four scenes. The user visually tested 0.5.0 and said it looks OK, so the heat renderer and engine were left alone. One harness issue found during review: stopping a run after some completed cases could yield a passing summary for a *partial* matrix. The summary now requires the expected row count and reports `incomplete` when stopped.

## Design and changes

- `tests.html`: separate, opt-in **Couplings × scenes** button and table. The ordinary full and quick matrices are unchanged. Five engine scene presets × (untouched baseline + six engine coupling presets) = 35 rows; preset IDs and settings are read from `PRESETS`/`PRESET_BY_ID` rather than copied into the harness.
- The shared perf runner applies each scene's complete settings, re-deals the bed, then applies only the coupling's live `size`, `arch`, and `buoyancy` settings. The whole deal is seeded with `0x9e3779b9` for a matched comparison; the field's `feed` remains the scene's own. The same view and DPR 1 are used for each scene and its couplings.
- After 420 warm + 60 timed frames (8 s simulated at 60 Hz), each row records T<0.483 cold beads, bonds with stiffness ≥0.02, mean bead T, beads above water, and frame/sim/render/rAF p95. Table and log show differences against that *scene's* baseline, not against the shipped thermal scene. A non-finite state or over-budget callback fails its row. This is a short-run comparison; 20 s drift still needs a longer sweep before changing presets.
- The matrix is separate because 35 × 480 rAF frames take about 4–5 minutes at 60 Hz. It uses the normal Stop and save/copy-log paths, and a stopped run cannot pass as complete. `VERSION` bumped to 0.5.1; README and `0.5-draft.md` updated.
- `experiments/harness.js` verifies the 5×7 case list and ordering, runs all 35 rows with very short frame overrides in the fake DOM, checks that every coupling retunes the three live fields without changing scene feed or bead count, reruns the seeded baseline to confirm identical output, checks grouped log rows, and guards incomplete summaries. This validates plumbing, **not** browser pixels, 8 s outcomes, or real frame budgets.

## Validation

`python3 run_tests.py --node-only`: seven node checks pass; log `experiments/logs/0.5.1-tests-2026-10-26-08-20-00.log`. The harness sandbox runs nine browser checks plus the 35-row matrix with shortened frames. A separate one-off Node sweep of the actual 480-frame matrix (same seed/deal and engine, no canvas) shows the scene dependence the table is meant to expose: `heat / shrinkStable` falls from 203 to 96 links and mean T rises 0.61→0.85, while `balanced / growConvection` rises from 1086 to 1904 links and mean T falls 0.64→0.32; `sparseRaft / shrinkStable` falls from 507 to 158 links. These are 8 s observations, not preset recommendations. After the final table/markup edit, `node experiments/harness.js` passed again (17 referenced IDs, nine checks, all 35 short matrix rows). Real browser pixels and frame costs have not been measured here. No engine physics changed.
