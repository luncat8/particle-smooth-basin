# 0.2 thermal hydrogel basin

## goal

Give each bead a temperature in 0..1, drive it with a cold upper zone and a hot lower zone, and let temperature change bead size, color, and cohesive links. Expose the main model parameters as controls while keeping the page local-file friendly and the simulation hot path allocation-free.

## model

### temperature field

- `temp: Float32Array`, one value per stable bead index; initialize to 0.5.
- Temperature is bounded to 0..1. A cold source covers the upper ~24% of the canvas and grades from near 0 at the top to ~0.2 at its lower edge. A hot source fades in over the bottom ~22% and reaches 1 at the floor.
- Source relaxation and bead-to-bead conduction have independent controls. Conduction uses the existing spatial pair list and a preallocated delta array so each substep uses a simultaneous update rather than pair-order-dependent mutation.
- No latent heat, phase state, or energy conservation claim: this is an interactive normalized-temperature model. At zero source and conduction rates, temperatures are unchanged.

### temperature-dependent size

- The typical-size control sets the collision radius at temperature 0.5.
- Signed size response `s` is in [-1, 1]. Radius multiplier is `2^(s * (temp - 0.5))`: at full positive response the hot/cold endpoint radius ratio is 2; negative response reverses it; zero disables thermal sizing.
- Radius, contact distance, grid bound, render radius, and mass are kept consistent. The 2D mass model remains density times radius squared times an average-mass scale; buoyancy continues to use the independent density ratio.

### archimedes response to size

- Signed response `a` in [-10, 10] scales the buoyant part of gravity by `(r / typicalRadius)^a`, with the resulting lift multiplier bounded to 1/8..8 for stability. Default 0 keeps buoyancy independent of size: thermal size can shape flow without silently changing floating. Positive `a` makes larger beads more buoyant; negative `a` makes smaller beads more buoyant.
- Independent buoyancy strength `b` in [0, 2], default 1, scales the Archimedes term. Density and mass retain their existing models.

### thermally activated cohesion

- Reuse the PBD distance-constraint seam, not explicit stiff Hooke forces: force springs stiff enough to preserve a cluster need a smaller timestep and can become unstable. PBD projection remains stable at the existing 120 Hz.
- Each substep rebuilds the cold-bond set from broadphase near-neighbor candidates. When a pair is near contact and its mean temperature is below 0.55, create one bond with its rest distance recorded relative to the sum of the two current radii (minimum ratio 1.01 so the bond cannot demand overlapping beads). Cold increases stiffness; warmth removes the bond. Pairs stretched beyond the broadphase radius also thaw, so no invisible long-range constraints remain.
- Solve bonds after contact projection in the existing relaxation iterations. Contacts retain priority to prevent overlap. Stable append-only particle indices remain required.
- Keep all cold bonds in the public link arrays, but partition bonds above a small stiffness threshold to the front. The solver, renderer, and stats scan only that effective prefix; weak bonds retain a rest entry so cooling can strengthen them without changing rest distance.
- Use two bounded open-addressed pair-key tables, swapped each substep, to carry rest distances between frames. Cache grid cell indices and pair radius sums from broadphase. Pair and link buffers grow together only on exceptional overflow. No per-frame objects or arrays.

## controls

- Thermal source relaxation: 0..4×, default 1; live adjustment.
- Bead-to-bead conduction: 0..4×, default 1; live adjustment independent of source strength.
- Thermal size response: -1..1, default 0; live adjustment.
- Archimedes force vs size: -10..10, default 0; live adjustment.
- Buoyancy strength: 0..2×, default 1; live adjustment.
- Quick scenarios set the thermal-size and Archimedes-size pair for shrink-flow, big-floats, convection-style, and stable-layering experiments without changing the other rates.
- Canvas coverage: 30..70% of the canvas area when particle disc areas are summed at typical radius. This determines particle count for current dimensions; display the resulting count and honor the spawn cap. The spawn cap may limit the top end on large canvases or at the smallest radius.
- Typical radius: 8..22 px at temperature 0.5.
- Average mass scale: 0.4..2.5, default 1; live adjustment without changing buoyancy density.
- Temperature-color view toggle plus a normal density-color view.
- Re-deal/reset applies count, coverage, and typical-radius changes. Resizing re-deals with the current controls so the requested coverage remains meaningful.

## view and interaction

- Pre-render a temperature palette once; render the current temperature as hue when enabled. Density palette remains the default view.
- Render the hot and cold zones as subtle cached gradients/bands so the thermal sources are legible without obscuring the beads.
- Keep pointer grab/stir, click-to-add, splash, and reset interactions. Added beads begin at 0.5 and subsequently exchange heat with their environment.

## implementation seams

- `js/engine.js`: temperature storage and update, dynamic radii/mass, coverage-based bed sizing, hot/cold source field, cached broadphase geometry, bond collection/solve, fixed-step wave field, public settings helpers.
- `js/render.js`: cached zone fills, static tank `Path2D` outlines, and pre-rendered temperature sprites.
- `js/app.js` + `index.html`: controls, labels, input wiring, temperature-view toggle.
- `experiments/bench.js`: seeded physics throughput and link-capacity baseline; temperature bounds, independent rates, size response, bond activation/thawing, spawn coverage, pointer gating, wave timing, and buoyancy sanity.

## validation

- Zero source and conduction rates leave temperature unchanged; each rate works independently; all values remain in [0,1].
- Positive size response makes hot beads larger than cold beads, negative reverses it, and zero leaves the typical radius independent of temperature.
- Zero Archimedes-size response preserves size-independent buoyancy; positive response lifts a double-radius neutral bead while a typical-radius bead hovers; negative response sinks the large one. Extreme size exponents remain bounded.
- Buoyancy strength 0 removes lift, 1 preserves the original equilibrium, and 2 increases lift.
- Cold touching beads create one bond with a persistent rest length; warming or excessive stretch removes it. Effective link count never exceeds cold link count or pair count; link solving remains finite and contacts do not invert bead separation.
- Coverage settings produce the expected canvas-area fraction within count quantization when below `SPAWN_CAP`; otherwise the UI-reported count is capped.
- Existing Archimedes equilibrium and splash stress remain valid; no NaN at default settings or extreme slider combinations. Temperature stays in [0,1] even with source-only heating above the canvas.
- Hovering never applies pointer force; a held pointer does. Pointer cancel does not add a bead. Wave state is identical under 60 Hz and 120 Hz frame schedules for the same simulated time.
- Browser smoke: controls update, view toggle switches palettes, resizing and DPR changes preserve settings, and file:// uses no external assets.
