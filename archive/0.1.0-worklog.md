# 0.1 worklog

## prototype review

four prototypes were compared before writing the base (all implement the
draft.txt brief: basin of hydrogel beads, water at 50%, archimedes,
random weight/size, 70% fill).

| | claude-opus-5.5-low | prototype-particle-GPT6L | GLM53f | qwen38max |
|---|---|---|---|---|
| form | single html, 157 ln | single html, 372 ln | single html, 679 ln | 5 js + css, ~1.6k ln |
| waterline | 50% ✓ | 80% ✗ (brief says 50%) | 50% ✓ | 50% ✓ + displacement rise |
| submerged fraction | smoothstep approx | exact segment | exact asin ✓ | exact segment |
| mass model | r³·ρ (3D, wrong in 2D) | area·ρ ✓ | ρ·r² ✓ | area·ρ ✓ |
| contacts | spring force + damping | impulse + restitution (bouncy) | PBD soft projection, calm ✓ | spring force + friction + separate O(n²) relax |
| broadphase | Map grid, allocs per frame | none, O(n²) | typed-array grid ✓ | none, O(n²) twice |
| timestep | fixed 8 substeps | fixed 3 substeps | accumulator 120 Hz ✓ | accumulator 240 Hz |
| bead rendering | radial gradient / bead / frame ✗ | gradient / bead / frame ✗ | pre-rendered sprites ✓ | canvas sprite per bead (heavy) |
| waves | sine fake, visual only | none | 1-D spring field, 2-way kick | field + drops/bubbles, field allocs per pass ✗ |
| hot-path allocs | Map, lists, color strings ✗ | gradients ✗ | near zero ✓ | `new Array` in wave pass, Path2D/grads per frame ✗ |
| runtime rules (AGENTS) | ✓ | ✓ | ✓ | ✗ tailwind CDN + google fonts |
| extras | stir, reshuffle | add-on-click | grab/toss/add/splash/stats | control panel, stats, pot geometry |

verdict: GLM53f is the only prototype that hits the brief exactly and
obeys the no-allocation hot path; qwen38max has the richest look but
violates runtime rules and repeats O(n²) work; GPT6L is clean but
misses the 50% waterline and uses O(n²); claude is a sketch with
per-frame allocation and an approximate buoyancy.

## decisions

- base architecture from GLM53f: PBD pipeline, typed-array grid, sprite
  palette, wave field, accumulator, spawn bed, tank layout.
- physics correctness from GPT6L/GLM: exact circular-segment submerged
  fraction, 2D mass (ρ·r²), density mix with float/hover/sink classes.
- visual gap between packed beads (RENDER_SHRINK) from the brief; qwen's
  density-linked color idea kept as light/deep palette split.
- qwen's pot geometry, control panel, drops/bubbles, displacement-level
  rise: out of scope for the base (clean architecture; the pot wall
  solver is heavy and not in the brief). CDN fonts/tailwind dropped —
  file:// + no internet links is a hard rule.
- storage as SoA typed arrays with stable indices, not an object array:
  cache-friendly, node-requireable, and link endpoints (0.2) can point
  at beads safely.
- `pairRF` seam: pair scan radius factor (default 1). 0.2 widens it for
  link discovery; contact solve already skips non-overlapping pairs so
  one pair list serves both.

## issues found in the prototypes (fixed in the base)

1. elastic micro-contacts. PBD projection re-injects its corrections as
   separation velocity. with mixed densities a squeezed pile never
   rests: measured mean|v| = 13 px/s forever (positions static, beads
   vibrating in place; light beads trapped at the floor were worst).
   neither more iterations nor stiffer projection helped. fix: damp
   normal relative velocity of touching pairs after velocity derivation
   (CONTACT_DAMP = 1 — hydrogel is inelastic). pile settles to
   mean|v| = 0.4, splash still lively and decays to rest in ~10 s.
2. wave/beam resonance pump (GLM's "two-way coupling"). a bead bobbing
   on its own meniscus at the wave field's natural frequency (~8.9 rad/s
   vs ~10.8 rad/s bobbing) gains energy forever; a lone ρ=0.5 bead never
   settled and the bed stayed hot. smoothing the surface for buoyancy
   only reduced the gain. fix: archimedes reads the flat tank level
   (as physically defined); wave field is visual + receives the kick,
   and the bead pays the opposite impulse (radiation damping). lone bead
   settles at exactly f = ρ.
3. prototype perf issues not carried over: per-frame Map/grid
   allocation (claude), O(n²) broadphase (GPT, qwen ×2), gradients per
   bead per frame (claude, GPT), `new Array` inside the wave pass and
   Path2D/gradient rebuild per frame (qwen), pair buffers that silently
   drop pairs when full (GLM — base grows instead).

## implementation

- `js/engine.js`: world, wave field, particles, grid/pairs, substep,
  pointer, splash; `module.exports` guard for node.
- `js/render.js`: sprite builder (12 palette entries), cached gradient
  assets, water/tank/waterline drawing.
- `js/app.js`: fit/dpr, debounced resize, pointer + keys, fps/hud, loop.
- `index.html`: page shell with local styles only.
- `experiments/bench.js`: throughput + sanity checks.

## validation

`node experiments/bench.js` (node v22, 1280×800, log in
experiments/logs/0.1.0.txt):

- throughput 0.28 ms/frame for 656 beads (physics, ~3500 fps headroom),
  zero steady-state allocations (typed arrays grown only at spawn/resize)
- 60 s settle: NaN = 0, mean|v| = 0.4, max|v| = 6 — pile at rest
- distribution: ~50 beads fully above the waterline (crowding pushes
  them out ✓), ~550 fully submerged (sinkers ✓), mean submerged 0.88
- exact archimedes equilibrium: lone bead ρ=0.5 settles at f = 0.500,
  ρ=2.0 rests on the floor at f = 1.000
- submergedFrac analytic spot checks pass (f(0)=0.5, endpoints exact)
- splash stress: no NaN, max|v| ≈ 140 immediately, back to rest in ~10 s
- render/app smoke-tested under a DOM mock (12 sprites, 150 frames,
  R + SPACE handlers) — no reference errors
