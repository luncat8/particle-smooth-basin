# 0.3.1 browser tests in one command worklog

## review of 0.3.0

- The `?profile=1` timer did what it promised, but the recorder lived inside `js/app.js`, so only the live page could produce a frame profile. The plan's matrix (300/810/1500 beads × DPR 1/2 × temperature view, cold/high-link preset) had to be driven by hand, case by case, and the result read off a stats line or copied out of a console — nothing to compare between runs.
- `experiments/smoke.js` had already grown its own fake DOM. Adding a second browser-facing page would have copied that sandbox a third time.
- `experiments/bench.js`, `thermal.js`, `smoke.js` and `index.html?profile=1` were four separate commands with four separate outputs, so a single change had no single artifact.

## implementation

- `js/profile.js` now owns the timing: `createSamples(frames)` is one preallocated channel with p50/p95, and `createProfiler(frames)` is the three-stage frame/sim/render timer built from it. `js/app.js` records into it and reports exactly as before (`PROFILE 300F · FRAME p50 … · SIM … · RENDER … MS`); it also exposes `window.__profile` for a driver. Nothing is measured or formatted while `?profile=1` is absent.
- `tests.html` is the browser harness. It loads the shipped `js/engine.js` + `js/render.js` + `js/profile.js` (no HUD) and runs:
  - checks: `boot` (spawn count, wave columns), `canvas` (beads repaint the canvas — empty world versus populated world, pixel diff, honest skip when there is no rasterizer), `invariants` (120 frames with splash and drag: link/pair capacities, finite state, temperature 0..1, side walls and floor), `interaction` (click adds one bead, pointer cancel adds none, a held drag moves the bead it grabbed, splash leaves a wave), `resize` (700×420 at DPR 2 re-deals, restoring 1280×800 restores the count), `thermal` (4× sources give a temperature spread, radii stay inside the size-response bounds, negative response shrinks the hot tail), `profile` (one report at exactly N frames, then silence);
  - the perf matrix: `light` 302 beads / `default` 810 / `cap` 1500, each at DPR 1, DPR 2 and DPR 1 with the temperature palette, plus `cold-links` (240 warm-up frames on the cold, high-link preset) and `stirred-cap` (near-cap scene under a held drag and a splash). Each case records p50/p95 for the callback, `stepWorld`, `render`, and the rAF interval — the interval is what exposes compositor cost that callback timing hides;
  - output: a table, a visible log, `Save log`, `Copy log`, and an auto-save checkbox. The log ends in one `RESULT pass|fail · checks … · perf … · worst p95 …` line.
- `run_tests.py` is the single entry point. No arguments: it runs `experiments/smoke.js`, `thermal.js`, `bench.js` and `harness.js` (echoed into one timestamped log), then serves the repo with `Cross-Origin-Opener-Policy`/`Cross-Origin-Embedder-Policy` and `no-store`, and opens `tests.html`, which auto-runs the full matrix. The page POSTs its section to `/__log`; the server appends it to the same file. `Save log` re-sends it, and `Copy log` copies it. Flags exist for the awkward cases (`--no-open`, `--port`, `--host`, `--skip-node`, `--node-only`), but the default is the double-click.
  - The server exists for two reasons: cross-origin isolation keeps `performance.now()` at microsecond resolution instead of 100 µs, and a POST target is what turns "copy the console" into a saved artifact. `file://` still works — Save then downloads instead.
- `experiments/fake-dom.js` is the sandbox from `smoke.js` extracted into a factory (`createSandbox`) with manual or timer-driven frames, mutable DPR/viewport and a canvas stub. `smoke.js` and the new `experiments/harness.js` both use it.
- `experiments/harness.js` validates the page without a browser: extracts the inline script, compiles it (`vm.Script`), checks every element id the script asks for exists in the markup, boots the page in the fake DOM, runs all seven checks, runs one perf case at tiny frame counts, exercises `summarise`, then runs `run("quick")` with a fetch stub and asserts the posted log carries the environment line, checks, perf rows and a `RESULT pass`, and that the status line keeps the verdict after saving.

## validation

- `node experiments/harness.js` — pass: 13 ids referenced and present, 7 checks ok, quick matrix 2 cases, `run("quick")` posted one pass log.
- The full matrix was also driven once through the same fake DOM (`harness.run("full")`): 11 rows, 302/810/1500 beads, cold-links 185 active links, stirred-cap 627, `RESULT pass · checks 7/7 · perf 11/11 within 16.7 ms · worst p95 13.66 ms (cap dpr2)`, 20.9 s wall with a no-op canvas. Those stage times are the node engine plus a proxy context, not browser frames; only the shape of the run is validated.
- `node experiments/smoke.js` — pass, unchanged assertions, including the deterministic `?profile=1` fake-clock profile (frame 2.50 ms, sim 1.25 ms, render 1.25 ms).
- `node experiments/thermal.js`, `node experiments/bench.js` — pass; bench 810 beads 0.38 ms/frame, near-cap 1500 beads 1.07 ms/frame, no NaN, equilibrium 0.500/1.000. Numbers in `experiments/logs/0.3.1.txt`.
- `python3 run_tests.py --node-only` — pass, four checks, correct timestamped log.
- Server path checked by hand in the sandbox: `tests.html` serves 200 with `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp` and `Cache-Control: no-store`; `POST /__log` appended a browser section to the open run log and answered `{"saved": true, "path": …}`.
- No browser exists in this sandbox, so the canvas pixel check, the real matrix numbers and the export line have not been observed in a browser here. `experiments/harness.js` covers selectors, engine calls, profiler math and the save path; everything about actual frames still needs `python3 run_tests.py` on the target machine.
