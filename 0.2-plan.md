# 0.2 freeze links

## goal

links between near particles that act like freeze: a frozen region keeps
the relative positions of its beads and moves like a solid chunk through
the water; on thaw it flows like the rest of the fluid.

## model

"force-links" = stiff distance constraints solved by projection in the
contact relaxation loop (PBD), not spring forces:

- springs stiff enough to hold a chunk need dt well below 1 ms or they
  explode/jitter; the sim runs SUBSTEP = 1/120 s
- projection is unconditionally stable and reuses the existing
  relaxation loop (solveContacts iterations)
- several iterations at full stiffness converge to a rigid cluster,
  which is exactly "acts like freeze"

rest length = distance at link creation time (current packing; no
lattice assumption). optional separate bend/angle constraint is not
needed for the first cut — a triangulated neighbor graph of distance
constraints is rigid enough.

## data (mirror the pair buffers)

created at createWorld, never per-frame:

- `linkA, linkB: Int32Array` — bead indices (stable: the base appends
  and never removes/reorders beads; if removal ever lands, links must be
  remapped in the same step)
- `linkRest: Float32Array` — distance at creation
- `linkK: Float32Array` — stiffness 0..1 (ramp down for soft melt)
- `linkN` — count

cap ~4 · SPAWN_CAP, grow helper like pairTest's. keep links sorted-free
(swap-with-last removal is fine).

## creation

- `freezeRegion(world, x, y, radius)` — beads with center inside radius
- `freezeAll(world)`
- neighbor discovery: run collectPairs with `world.pairRF ≈ 1.15`
  (seam already in engine); contact solve ignores non-overlapping pairs,
  so the same pair list covers contacts and link candidates
- for each pair closer than `LINK_R · (ri + rj)` (LINK_R ≈ 1.15) with no
  existing link: create link with `rest = current d`
- dedupe via a per-bead neighbor-list walk or a stamped mark array
  (Int32 stamps, cleared by generation counter — no clearing sweep)

## solving

inside the solveContacts iteration loop, after contact projection:

- `solveLinks(world)`: for each link, project current distance toward
  `rest` by `linkK`, mass-weighted exactly like contacts
- per-iteration order: contacts first (keep gaps), links second (keep
  shape); iterate together so clusters go rigid as a whole
- grab/stir/splash need no changes: dragging one bead pulls the chunk
  through the links, splash tosses the chunk coherently

## melt

- `thawRegion(world, x, y, radius)` / `thawAll(world)`
- removal: swap-with-last over the link arrays
- optional softening: ramp `linkK` toward 0 over ~1 s before removing
  (ice softening) — a single global thaw is enough for the first cut
- no fracture/tension breaking in 0.2 (links never break under load)

## visuals

- frozen beads: cool tint overlay (translucent pale-blue circle at
  RENDER_SHRINK radius, single pass over frozen beads)
- links: one batched path of faint segments between linked centers;
  skip drawing when linkN is large or only draw while interacting

## interaction (first cut)

- `F` — freeze all beads near the waterline? simplest: freeze all
- `T` — thaw all
- region freeze via click with a modifier can follow later

## validation

- bench addition: freeze a block of ~100 beads, splash, run 10 s: no
  NaN, max link stretch < 1% of rest, chunk translates as one body
- thaw: beads flow again and settle to mean|v| < 1 like the fluid bed
- throughput: 650 beads + ~2k links well under 2 ms/frame in node
